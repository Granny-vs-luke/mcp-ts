## New features

### Neon storage backend

You can now persist MCP sessions on Neon's serverless Postgres with the new [Neon storage backend](/storage-backends/neon). It ships with optional Row-Level Security configuration and a `pg_cron` cleanup job for expired sessions, alongside ready-to-run migrations. See the updated [storage backends overview](/storage-backends/overview) for how it compares to Redis, Supabase, SQLite, and the file system.

### CodeMode

CodeMode is a new execution mode that lets the LLM write and run small TypeScript snippets in an isolated sandbox. Instead of issuing one tool call at a time, the model can call your MCP tools as plain async functions (for example, `github.get_issue(...)`). CodeMode auto-generates TypeScript interfaces for connected servers and exposes four built-in tools for searching, listing, inspecting, and chaining tool calls. The sandbox runtime ships as an optional dependency.

### Tool Router as a standalone package

The [Tool Router](/core-concepts/tool-router) is now available as its own installable package, so you can drop it into any agent or framework without pulling in the rest of mcp-ts. The five default [meta-tools](/core-concepts/meta-tools) (`mcp_search_tools`, `mcp_get_tool_schema`, `mcp_execute_tool`, `mcp_list_servers`, and the namespaced lookup helper) work the same way as before.

## Updates

### Deeper tool search

[`mcp_search_tools`](/core-concepts/meta-tools) now indexes words from nested argument schemas, including object properties, array item types, and enum values. Previously, search only covered the top-level tool name and description. The LLM can now find a tool by terms that only appear inside its input schema, which improves recall on large MCP servers without changing the response shape.

### Standardized client API

We aligned the client and storage APIs around consistent naming so the same concept reads the same way everywhere:

- The user identifier passed to clients, storage backends, and hooks is now `userId` (previously `identity`).
- The Streamable HTTP transport type is now spelled `streamable-http` consistently across config, [client](/reference/client), and [server](/reference/server) options.
- Session data accessors on storage backends use clearer names — see the [storage reference](/reference/storage) for the current method names.
- SSE client URL and header construction is simpler, and the client now trims and ignores empty or whitespace-only header values before connecting.

If you're upgrading from v1.6.x, rename `identity` to `userId` and update any `streamableHttp` transport strings to `streamable-http`.

### Tool approvals and annotations

The tool approval flow now returns a more consistent payload to apps using the [React](/react) or [Vue](/vue) hooks. Tool definitions no longer carry annotation fields, which simplifies the [tool types](/reference/types) — annotations are no longer required on the wire.

### Optional peer dependencies

`json-schema-to-zod` and `isolated-vm` are now optional. Install them only if you're generating Zod schemas from MCP tool schemas or running CodeMode, respectively. This keeps the default install slimmer.

## Bug fixes

- **SSE header construction** — The client now trims header names and values and skips empty entries, so malformed optional headers no longer leak into connection setup.
- **Tool search regressions** — Fixed cases where nested schema fields prevented matches on otherwise valid search terms.
