## New packages

### `@mcp-ts/codemode`

Code Mode now ships as a standalone, zero-dependency execution engine that lets an agent run JavaScript inside a V8 sandbox to orchestrate multi-step tool workflows.

- Sources are exposed as JavaScript namespaces (for example, `github.list_pull_requests(args)`), so the LLM can write natural, synchronous-looking code.
- TypeScript interfaces for each tool are generated automatically and injected into the sandbox.
- Configurable limits for timeout, memory, tool calls, concurrency, result size, and log volume.
- Four ready-made Vercel AI SDK tools: `codemode_search_tools`, `codemode_list_sources`, `codemode_tools_info`, and `call_tool_chain`.
- Optional MCP server wrapper to expose the runtime over `stdio` or HTTP.

See the new [Code Mode](/core-concepts/code-mode) guide.

### `@mcp-ts/tool-router`

The tool router is now also available as a separate package for projects that do not use `@mcp-ts/sdk`. It indexes any set of tool sources and exposes four meta-tools — `toolrouter_search_tools`, `toolrouter_list_sources`, `toolrouter_get_tool_schema`, and `toolrouter_call_tool` — so the LLM only sees the active catalog when it needs to.

- Works with any source that implements `listTools` and `callTool`, including non-MCP HTTP APIs.
- Built-in `mcpSource` and `mcpSources` adapters wrap MCP clients in one line.
- Policy gates: `allowTools`, `denyTools`, `denyDestructiveTools`, and an async `approveToolCall` hook for human-in-the-loop.
- First-class Vercel AI SDK integration via `createAISDKTools`.

See the updated [Tool Router](/core-concepts/tool-router#standalone-package) guide for usage.

## Removals

The deprecated `packages/mcp-server-docs` documentation server has been removed. Documentation is served directly from this site.
