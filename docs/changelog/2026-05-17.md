`mcp-ts` v2.0.0 is here. This release ships two new standalone packages, renames the storage API, and standardizes user identifiers across the SDK. See the [v2.0 migration guide](/migration) for upgrade steps.

## New packages

### @mcp-ts/code-mode

A sandboxed execution engine that lets an LLM run JavaScript inside a V8 isolate to orchestrate multiple MCP tool calls in a single turn. Sources are exposed as namespaced async functions (for example, `await github.list_pull_requests({...})`), and TypeScript interfaces are generated automatically.

```typescript
import { createCodeModeRuntime } from "@mcp-ts/code-mode";

const runtime = await createCodeModeRuntime({
  sources: [githubSource],
  limits: { timeoutMs: 5000, memoryLimitMb: 64, maxToolCalls: 10 }
});

const result = await runtime.run(
  `return (await github.list_pull_requests(input)).filter(p => p.state === "open");`,
  { owner: "zonlabs", repo: "mcp-ts" }
);
```

See [Code Mode](/core-concepts/code-mode) for full configuration, limits, and AI SDK integration.

### @mcp-ts/tool-router

A standalone package for searching, fetching schemas, and routing tool calls across many MCP servers without bloating LLM context. The model sees four meta-tools and discovers real tools on demand.

```typescript
import { createToolRouter, createAISDKTools } from "@mcp-ts/tool-router";

const router = await createToolRouter({ sources: [github, slack] });
const tools = await createAISDKTools(router);
```

See [Tool Router Package](/core-concepts/tool-router-package) for sources, policies, and adapters.

## Breaking changes

### Sessions API

The `storage` object has been renamed to `sessions` to better reflect its purpose.

```typescript
// Before
import { storage } from "@mcp-ts/sdk";
const userSessions = await storage.getSessions(userId);

// After
import { sessions } from "@mcp-ts/sdk";
const userSessions = await sessions.list(userId);
```

### useMcp hook

The React `useMcp` hook now accepts `userId` instead of `identity`.

```typescript
// Before
const { tools } = useMcp({ identity: "user_123" });

// After
const { tools } = useMcp({ userId: "user_123" });
```

### Database migrations

Database-backed storage solutions (Supabase, Neon, SQLite, and other SQL backends) require a schema migration to align with the new `sessions` and `userId` terminology. Migration scripts ship in the `migrations` directory of the `mcp-ts` repository. Apply the script for your backend before deploying v2.0.0 to production.

For full upgrade instructions, see the [v2.0 migration guide](/migration).
