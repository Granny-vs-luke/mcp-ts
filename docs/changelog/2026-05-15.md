## New features

### Neon storage backend

You can now persist MCP sessions in [Neon](/storage-backends/neon) serverless Postgres. Set `MCP_TS_STORAGE_TYPE=neon` and `NEON_DATABASE_URL` to opt in. It's a good fit for serverless deployments that want durable session storage without running Redis.

Highlights:

- Uses the optional `@neondatabase/serverless` peer dependency and Neon's HTTP query API.
- Includes ready-to-run migrations for the `mcp_sessions` table and an optional `pg_cron` cleanup job.
- Documented role setup and optional row-level security for production.

### Custom human-in-the-loop approvals

The AI adapter accepts a new `needsApproval` callback so you can decide on a per-call basis whether a tool requires user confirmation before running. The callback receives the tool and its arguments and may return a boolean or a `Promise<boolean>`.

When you don't provide `needsApproval`, the SDK falls back to the previous behavior of checking the tool's `destructiveHint` annotation, so existing integrations keep working unchanged. The Tool Router's `mcp_execute_tool` meta-tool participates in approvals by inspecting the underlying target tool.

### Nested tool schema search

The [Tool Router](/core-concepts/tool-router) now indexes nested fields inside each tool's input schema — including argument names, descriptions, and enum values — so semantic searches surface tools that match deep schema metadata, not just top-level names and descriptions. Search quality improves noticeably for tools with rich parameter schemas.

## Updates

### Standardized session API naming

Session management methods now share a consistent vocabulary across the server SDK, every storage backend, and the React and Vue client adapters. See the [Storage API reference](/reference/storage) and [Client reference](/reference/client) for the full surface.

Server / storage:

- `getUserSession` → `listSessions`
- `getUserSessionIds` → `listSessionIds`
- `getAllSessionIds` → `listGlobalSessionIds`
- `removeSession` → `deleteSession`
- `clearAll` → `clearGlobalSessions`

Client:

- `getSessions` → `listSessions`
- `restoreSession` → `getSession`
- `RestoreSessionResult` → `GetSessionResult`

### `userId` replaces `identity`

Session ownership is now expressed as `userId` everywhere — across `MCPClient`, storage backends, tests, and README examples. The change makes the parameter's intent unambiguous when integrating with your existing auth system.

### Transport name standardized to `streamable-http`

The Streamable HTTP transport is now identified consistently as `"streamable-http"` across client hooks (`useMcp` for React and Vue), connect forms, OAuth client, and the Neon backend. Update any hard-coded transport strings to match.

### `json-schema-to-zod` is now an optional peer dependency

`json-schema-to-zod` moved from a direct dependency to an optional peer dependency. Install it only if your integration converts JSON schemas to Zod at runtime, which keeps the default install footprint smaller.

### Simpler SSE client and Next.js handler

URL and header construction in the SSE client and the Next.js handler has been simplified, removing redundant branches and making custom header passthrough more predictable.
